# バックアップ

「設定」から、問題集・学習履歴・設定を1つの`.fukushu`ファイルへ保存し、別のブラウザで復元できます。画像・音声・元APKGもファイル内に含むため、元ファイルを別途用意する必要はありません。以前に作成したJSONバックアップ（version 1〜3）も読み込めます。

## 含まれるデータ

- 問題集、問題・解答・解説、テンプレートとCSS、出題順。
- 回答履歴、FSRS状態、次回復習日時、出題停止・保留の状態。
- 学習設定、言語、テーマ。
- 読み込み元情報、保存済みの元APKG、画像・音声。
- 読み込み操作の履歴（追加・変更・停止の件数）。旧JSONにこの履歴がない場合は復元できません。

学習途中の出題キュー・現在位置、オフライン用のアプリキャッシュは含みません。復元後は問題と学習状態から学習を再開します。

## 大容量への対応

旧方式は元APKGとメディアをすべてBase64文字列へ変換し、巨大なJSON文字列を作っていました。新方式ではバイナリをそのまま格納し、Blobの参照・スライスを使って書き出しと復元を行います。バイナリの検査は4MiBずつ読み込み、SHA-256を逐次計算します。総バイナリ容量に比例するArrayBufferやBase64文字列は作りません。

書き出しはIndexedDBの単一readonlyトランザクションからカーソルで読み、各レコードを順に格納します。同時に別タブが更新しても、ストア間で読み取り時点が混在しないようにしています。復元時はファイル全体のチェックサム・形式・参照関係・メディアのハッシュを検証してから、単一readwriteトランザクションで既存データを置き換えます。書き込み失敗やキャンセル時はトランザクションを中止します。

画面には処理中の状態を表示し、キャンセルできます。ブラウザへのダウンロード引き渡し後は、ブラウザのダウンロード一覧で完了を確認してください。

## 制限

- `.fukushu`は新しいFukushu用の形式です。旧バージョンのアプリやAnkiへ直接取り込むことはできません。
- 元APKGと展開済みメディアを両方保持し、圧縮はしません。バックアップは元APKGより大きくなることがあります。
- 端末のメモリ・ディスク・IndexedDB保存容量には依存します。プライベートモードでは通常のプロファイルと保存制約が異なる場合があります。復元では安全な置換のため、既存データと復元データを一時的に両方保持できる空き容量が必要になる場合があります。
- バイナリ以外の問題・履歴などは復元時にメモリへ保持します。JSONメタデータは1レコード64MiBまでです。総ファイルサイズにこの64MiB制限は適用しません。
- CSV／TSV由来のdata URL画像・音声は問題本文の一部として保持します。APKG用メディアと同じ分離格納には変換しません。
- 旧JSONの読み込みは互換性のため従来の一括JSON解析を利用します。新形式と同じ省メモリ性はありません。
- 暗号化は行いません。チェックサムは破損検出用で、第三者による改変に対する署名ではありません。

## 開発者向け形式

先頭はUTF-8の`FUKUSHU-BACKUP-1\n`です。後続の各レコードは「4バイトのlittle-endian JSON長」「UTF-8 JSON」「任意の生バイナリ」で構成します。JSONは`store`、`value`、バイナリがある場合の`blobSize`を持ちます。JSONのオブジェクトキーは辞書順に固定し、同一データの再書き出し結果が一致するようにしています。末尾64バイトは、それより前の全バイトに対するSHA-256の小文字16進文字列です。

`media`の`value.blobBase64`は空文字列を互換スキーマ用に保持し、実体は後続バイナリに格納します。`importSources`の`sourceArchive`も同様にバイナリへ分離します。欠落・重複・未知のレコードや範囲外の長さを拒否します。設定ストアが空の場合は既定設定を出力します。

実装は[backupArchive.ts](../packages/app/src/application/backupArchive.ts)、[分割ハッシュ処理](../packages/app/src/application/backupIO.ts)、[復元検証・保存](../packages/app/src/application/backup.ts)を参照してください。

## 検証方法

```sh
pnpm --filter app exec vitest run tests/backup-archive.test.ts tests/database.test.ts tests/apkg-real.test.ts
pnpm --filter app exec playwright test e2e/basic.spec.ts e2e/apkg.spec.ts --workers=1
ANKI_BACKUP_FILE=../../.cache/anki-corpus/kaishi-1.5k.apkg pnpm --filter app exec playwright test e2e/backup-large.spec.ts --workers=1
BACKUP_SYNTHETIC_MIB=600 pnpm --filter app exec playwright test e2e/backup-large.spec.ts --workers=1
```

大容量テストは明示した場合だけ実行します。実データの取得元は[公開コーパス](compatibility/apkg-public-corpus.md)に記録しています。通常のChromiumプロファイル（テスト出力先へ作成）でダウンロード後、全データ削除・復元・再書き出しを行い、2つのファイル全体のSHA-256一致を検査します。バックアップ中の4MiB超の`Blob.arrayBuffer()`呼び出しはテストで失敗させます。計測結果はPlaywrightの出力先の`measurement.json`へ保存します。

大容量の測定ではブラウザプロファイルとバックアップ本体も生成します。再実行時に出力先を上書きするため、個人のブラウザプロファイルは指定しないでください。`.cache/backup-validation-*`と`test-results`はGit管理から除外しています。

## 2026-09-11の大容量検証

通常のChromiumプロファイルで各1回測定しました。保存領域のquotaを上書きしていません。時間はブラウザからのダウンロード完了、復元後の件数確認・操作可能になるまでを含みます。

| 対象                                  |              バックアップ容量 |   保存 |    復元 | 結果                                            |
| ------------------------------------- | ----------------------------: | -----: | ------: | ----------------------------------------------- |
| Kaishi 1.5k（1,501問・4,345メディア） | 231,443,511 bytes（約221MiB） | 6.98秒 | 15.47秒 | 全削除後に復元し、再保存ファイルのSHA-256が一致 |
| 公式fixture＋600MiBの合成バイナリ     | 629,243,549 bytes（約600MiB） | 9.54秒 |  4.54秒 | 全削除後に復元し、再保存ファイルのSHA-256が一致 |

この試験は読み出し単位と復元内容を検証するもので、プロセス全体のピークメモリ（RSS）の測定ではありません。プライベートコンテキストでは600MiBの復元が保存容量不足になりました。端末やブラウザの保存制約がなくなるわけではありません。機械可読の結果・実装ハッシュは[大容量バックアップ検証結果](compatibility/backup-large-results.json)を参照してください。
