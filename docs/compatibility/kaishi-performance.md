# Kaishiの読み込み・画面表示負荷 — 2026-09-05

Kaishi 1.5k v2.4.2（1,501カード、108,690,108 bytes）を、ローカルproduction buildとPlaywright Chromiumで検証した。入力のSHA-256は[公開コーパスmanifest](apkg-public-manifest.json)に固定している。

## 修正内容

- 閉じている問題プレビューダイアログの中身を生成しない。開いたときだけ描画し、閉じるとiframe・メディアURL・監視を解放する。以前は全問題の閉じたダイアログでも表裏を描画していた。
- 問題集の一覧を50問ずつ表示する。一覧内のメディアは軽量なラベルにし、実際のHTML/CSS・メディアはプレビューで確認する。
- 学習キューでは新規／復習の対象を先に判定し、必要な問題だけを単一トランザクションでまとめて読み出す。新規1,500問・1日20問の回帰テストでは、問題の読出しが20件であることを検証した。以前は復習判定のループで新規カードも全件個別に読み出していた。
- 解析結果の差分準備をVueの更新後にまとめて起動する。カード変換中は約16msごとを目安にイベントループへ制御を返し、進捗・キャンセルを処理する（1枚の変換時間自体の上限ではない）。同一CSSの安全化結果を取込内で再利用する。
- workerとの入出力ArrayBufferをコピーではなく所有権移動で受け渡す。メディア重複判定はSetを使う。
- `/decks`の集計を問題集ごとの全件filter/sortから、状態・履歴各1回の走査に変更する。全状態・履歴の読み出し自体は残っている。

## 修正後の実測

空のブラウザDBから取り込んだ1回の測定。複数回中央値や修正前との同条件比較ではない。

| 操作                                       |     時間 |
| ------------------------------------------ | -------: |
| ファイル選択から保存可能になるまで         | 15,546ms |
| 保存から問題集詳細50件の表示まで           |  3,689ms |
| `/decks`へ直接アクセスして問題集リンク表示 |    133ms |
| 学習画面へ直接アクセスして回答ボタン表示   |    221ms |

問題集詳細の待機中iframeは0個。プレビューを閉じた後も0個であることを検証した。上記計測時の学習画面は最大1個だった。その後、現在の1問の正答を非表示で先読みする仕様に変更し、上限は表裏の2個としている（キュー全体は先読みしない）。学習開始後のV8使用ヒープは先読み追加前で約42.1MiBだったが、これはピークメモリでもブラウザ全体のメモリでもなく、Blob・WASM等を含めた総量ではない。

専用Chrome DevTools MCPが未接続のため、web-perfスキルの監査は実行せず、Playwrightの実ブラウザ操作とCDPの`Runtime.getHeapUsage`で代替した。CWVの測定値として扱わない。

## 再実行

```sh
ANKI_PERF_FILE=../../.cache/anki-corpus/kaishi-1.5k.apkg pnpm --filter app exec playwright test e2e/kaishi-performance.spec.ts --workers=1
```

実ファイルはGit管理せず、自動ダウンロードもしない。環境変数を指定しない通常E2Eではこの計測はスキップする。計測結果はPlaywrightの添付JSONにも記録する。
